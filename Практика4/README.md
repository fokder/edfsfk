# Практична №4 — обидва проєкти

Рішення `Практика4.sln` містить один Windows Forms проєкт `Проект1`
із двома формами: Form1 — сортування зображень, Form2 — хрестики-нулики.

## Відкривання у Visual Studio

1. Розпакуйте весь репозиторій та відкрийте `Практика4/Практика4.sln`.
2. Потрібні Windows, Visual Studio з компонентом .NET desktop development
   та .NET Framework 4.7.2 Targeting Pack.
3. Ctrl+Shift+B — зібрати; F5 — запустити Form1.
4. Кнопка **«Хрестики-нулики»** на Form1 відкриває Form2.
   Перша гра на цей час стає на паузу. Після закриття Form2 вона
   продовжується, якщо працювала до відкривання другого вікна.
5. Для коду або конструктора виберіть Form1.cs чи Form2.cs:
   F7 — код, Shift+F7 — конструктор [Design].
6. Ctrl+Shift+S зберігає зміни коду та форми.

Обидві форми та їхні файли Designer/resx підключено до `Проект1.csproj`.
Кожне відкривання Form2 починає нову партію; поле попередньої партії
після закриття Form2 не зберігається.

## Проєкт №1 — рисунок 1, сторінки 18–21

Ліворуч унизу коробка, зверху падає зображення; праворуч бали, час,
Start, Pause, End, як у методичці. Друга коробка та регулятор інтервалу
додані для виконання завдань.

Назви isDown, points, t, pictureBox1, label1, label2, timer1, timer2,
button1–button3 та обробники подій збережено. Зображення рухається
на 10 пікселів за timer1_Tick, час обчислюється командою
`t += 0.001 * timer2.Interval`. Початкові інтервали — 50 та 10 мс,
обидва таймери спочатку вимкнено. Рух мишею використовує
`this.PointToClient(Control.MousePosition)` із прикладу.

Виконано всі чотири завдання:

1. NumericUpDown задає timer1.Interval від 10 до 200 мс.
   Менший інтервал — швидше падіння.
2. Пропуск за нижню межу (Y > 500) віднімає 50 балів.
3. Після Start, пропуску чи сортування випадково вибирається кіт або собака.
4. Кота потрібно перетягувати в коробку «Коти», собаку — в «Собаки».
   Центр зображення має потрапити в межі потрібної коробки під час
   відпускання лівої кнопки. Правильна коробка додає 100 балів,
   неправильна віднімає 50. Відпускання поза коробками продовжує падіння.
   Бали можуть бути від’ємними.

Start починає гру або продовжує після Pause. Pause зупиняє рух і час.
End зупиняє гру, приховує зображення, обнуляє час і бали.
Лічильник часу тут навчальний, за інтервалом таймера, а не точний секундомір.

### Необхідні доповнення до надрукованого коду

- NewPicture об’єднує випадкову позицію та випадковий вибір картинки.
  Один Random використовується повторно, щоб не повторювати початкові значення.
- Перевірку X < 170 замінено перевіркою двох прямокутників коробок,
  як вимагає сортування. Це також перевіряє вертикальну координату.
- Падіння зупиняється у MouseDown. У Windows MouseClick надходить після
  MouseUp, тому буквальне `timer1.Enabled = false` у MouseClick залишало б
  картинку нерухомою після відпускання. Обробник MouseClick залишено,
  але він враховує стан гри й перетягування.
- Перетягування працює лівою кнопкою; захоплення миші запобігає втраті
  події відпускання. Втрата захоплення скидає isDown.
- End також оновлює написи часу та балів, а не лише змінні.

Зображення вбудовані через Form1.resx, абсолютні шляхи на зразок d:\cat.gif
не потрібні. Окремих картинок із прикладу в PDF немає, тому використано
ілюстрації Twemoji: кіт, собака й коробка. Джерела та ліцензію наведено
в Images/ATTRIBUTION.md. Вони видимі й у конструкторі Visual Studio.

## Form2: проєкт №2 з методички — рисунок 11, сторінки 21–22

Вигляд із методички: меню «Нова гра», «Про програму», «Кінець»,
tableLayoutPanel1 та дев’ять кнопок b1_1–b3_3 у сітці 3 × 3.
Додано пункт «Гра з ПК» з позначкою — завдання до другого проєкту.

Код зберігає `char WHO = 'O'`, `short movement = 0`, обробник
`buuton_click` (написання з методички), окремі гілки O та X,
усі вісім перевірок перемоги у кожній гілці, жовті O і зелені X,
скидання всіх дев’яти кнопок у «Нова гра» та Close у «Кінець».

Без позначки «Гра з ПК» двоє людей грають почергово.
З позначкою людина грає O, комп’ютер — X. Після ходу людини ComputerMove
вибирає випадкову вільну кнопку та викликає PerformClick, тому перевірка
перемоги залишається в тому самому buuton_click. Це простий випадковий
суперник, а не непереможний алгоритм. Зміна режиму починає нову партію.

Після перемоги або нічиєї поле блокується; «Нова гра» знову його вмикає.
На дев’ятому ході спочатку перевіряється перемога, потім нічия, як у прикладі.

## Перевірка

У хмарному середовищі немає C#/.NET Framework та Windows Forms.
Збірка, запуск і фактичне відкривання конструктора тут не виконані.
Перевірено структуру проєктів, XML ресурсів, наявність зображень і
підключення обробників. Логічні вирази перемоги перевірено окремо
на всіх 19 683 заповненнях поля; це не заміна запуску C# програми.

На Windows після збірки перевірте:

- Form1: Start, Pause, продовження, End, усі значення швидкості,
  пропуск, правильну й неправильну коробки для обох зображень,
  відпускання поза коробкою та повторне натискання Start.
- Form2: усі рядки, стовпці та діагоналі для O і X, нічию,
  перемогу на дев’ятому ході, заборону повторного ходу в зайняту клітинку,
  нову гру після завершення, обидва режими та перемикання між ними.
