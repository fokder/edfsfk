# Варіант 1 — Дослідна лабораторія

Створено структуру Equipment із п’ятьма полями, масив із десяти записів,
виведення всього масиву на екран та у файл і пошук обладнання за назвою.
Одна форма, звичайний масив, цикли for. Без бази даних та сторонніх пакетів.

## Запуск

Відкрийте `Індивідуальне1.sln` у головній папці репозиторію.
Потрібні Visual Studio на Windows, .NET desktop development
та .NET Framework 4.7.2 Targeting Pack.
Ctrl+Shift+B — збірка, F5 — запуск.
Виберіть Form1.cs: F7 — код, Shift+F7 — конструктор форми.
Зберігайте всю папку разом із рішенням, а не лише файл .sln.

## Поля структури

- Name — назва обладнання (string).
- IssuedTo — кому видано, прізвище отримувача (string).
- Quantity — кількість одиниць (int).
- IsIssued — стан: true — видано, false — повернуто (bool).
- IssueDate — дата видачі (DateTime).

Для повернутого обладнання зберігаються отримувач і дата попередньої видачі.
Це записи про обладнання та його стан, а не розрахунок складських залишків.
Одна назва може повторюватися для різних отримувачів або видач.

## Користування

Верхня таблиця показує всі п’ять полів усіх записів.
У правому полі введіть повну назву, наприклад `Мікроскоп`, і натисніть «Знайти».
Пошук показує всі збіги незалежно від стану «видано/повернуто».
Регістр та зовнішні пробіли ігноруються; частини слова не шукаються.
Результат містить назву, отримувача, кількість, стан і дату видачі.
Для довгого рядка результату доступна горизонтальна прокрутка.

Для додавання заповніть назву, кому видано, кількість і дату.
Позначка «Видано» означає, що обладнання ще не повернуте;
без позначки запис матиме стан «Повернуто».
Натисніть «Додати запис» — масив збільшиться на один елемент.
Ця кнопка додає новий запис, а не змінює старий.

«Зберегти все у файл» записує весь масив, а не лише результати пошуку.
Файл має кодування UTF-8; поля розділені табуляцією, перший рядок — заголовки.
Збереження ручне. Після закриття додані записи залишаються в записаному файлі;
новий запуск знову показує десять записів із коду. Завантаження з файла
та редагування записів не входять у наведені вимоги.

## Як пояснити викладачу

1. Equipment описує один запис, equipment — масив цих записів.
2. InitializeComponent створює форму з кнопками, таблицею та полями.
3. ShowEquipment проходить масив циклом і додає рядки до таблиці.
4. buttonSearch_Click порівнює поле Name кожного запису з уведеною назвою.
   StringComparison.OrdinalIgnoreCase означає порівняння без урахування регістру.
   Знайдені записи додаються до listBox1. Якщо збігів немає, з’являється повідомлення.
5. buttonAdd_Click перевіряє поля, створює Equipment, збільшує масив через
   Array.Resize й записує новий елемент в останню позицію.
6. buttonSave_Click відкриває SaveFileDialog і записує масив циклом через
   StreamWriter. using закриває файл; catch показує помилку запису.
7. Form1.Designer.cs містить розташування елементів і підключення Click,
   Form1.cs — дії програми, Program.cs — запуск головного вікна.

## Перевірка

У хмарному середовищі перевірено XML, файли, події, п’ять полів структури,
десять записів та очікувані вибірки початкових даних.
Компілятор C# і Windows Forms відсутні: збірка та запуск тут не виконані.

Після збірки на Windows перевірте:

- На початку таблиця містить 10 записів.
- `Мікроскоп` знаходить 2 записи: Коваль, 2 шт., видано; Шевченко, 1 шт., повернуто.
- `Термометр` також знаходить 2 записи; `Терези` — один; невідома назва — жодного.
- ` мІкРоСкОп ` дає ті самі два записи. Порожній запит викликає повідомлення.
- Після додавання кількість стає 11, новий запис знаходиться за назвою.
- Не допускаються порожні текстові поля та кількість менша за 1.
- Файл містить заголовок і всі записи з п’ятьма полями; скасування діалогу безпечне.
